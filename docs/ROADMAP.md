# 实施任务

以下按可独立验收的顺序推进，当前均未实现。

## M1：完成 Git tag 发布闭环

- [ ] 01 建立 Rust CLI、配置解析与本地 bare remote 测试夹具；确认可执行文件名称及本机 PATH 冲突情况。
- [ ] 02 实现单分支 `plan`：远端 SHA、版本线匹配、上一 tag、下一版本、完整提交区间；保存版本化计划。
- [ ] 03 实现单项 `run`：前置检查、tag 创建、push 和远端结果校验；覆盖重复运行与同名冲突。
- [ ] 04 实现 `message`：记录到模板、终端和文件输出，增加 `--copy`，验证空行及多提交展示。
- [ ] 05 扩展多分支发布、部分失败恢复和过期计划检测；验证不会切换分支或修改用户文件。
- [ ] 06 支持明确指定 tag 区间导入历史发布；补充用户文档和错误处理示例。

完成条件：PRD 首期验收全部通过。实际仓库的首次发布先生成计划，使用明确授权的目标验证远端操作。

## M2：用 Cargo 验证扩展性

- [ ] 07 调研并记录 cargo-release 的版本、接口和动作归属，先验证单包发布计划及隔离执行。
- [ ] 08 接入真实结果采集和失败恢复，将最终版本、提交与 tag 写入统一发布记录。
- [ ] 09 用 workspace 多包发布验证 schema，补齐与 git-tag 的共同后端契约。
